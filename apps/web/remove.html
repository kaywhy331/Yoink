Leaving Yoink · version {{YOINK_VERSION}}

Remove Yoink completely.

Yoink is a local install: everything it owns is a service, a folder, a Chrome extension and, on Windows, an optional capture app. Nothing is deleted for you. Work down this list in order; each step names what it removes and what it leaves.

1. Keep a copy, if you want one

Settings › Privacy › Download data saves your plans, calls, actions and outcomes as one JSON file. Admin › Operations › Workers › Back up now writes a full database copy next to the live database. Do this before step 4.

2. Stop the service

From the app folder run:

npm run release:local -- --uninstall

This stops and disables the yoink-local-api user unit and removes its unit file. It prints the remaining paths and deletes nothing else. Without the unit no cart add, call check or update can run.

3. Remove the Chrome companion

Open chrome://extensions, find Yoink and choose Remove. Chrome deletes the pairing credential, store permissions, delivery queues and cart handoffs the companion kept in extension storage. If the companion was loaded unpacked from a folder, that folder stays on disk until you delete it.

4. Delete the data directory

The data directory holds the database, its backup copies, local repair snapshots and the observer trust keys. It is data/ inside the app folder unless the unit or your shell set YOINK_DATA_DIR; Admin › Operations › Workers › Service and storage shows the exact path. Delete that directory only after step 2, and only once you have the copy from step 1 if you want one. This is the step that cannot be undone.

5. Remove the app folder and packaged files

The repository folder contains the compiled app (dist/), the packaged companion ZIPs (release/) and dependencies (node_modules/). Delete the whole folder once steps 2 and 4 are done.

6. Windows capture app (only if installed)

Settings › Apps › Yoink Capture › Uninstall. It is a separate experimental probe; removing the companion and service does not remove it.

What stays outside Yoink

Your store accounts, carts, orders and payment details were never stored by Yoink and are unaffected. TrackaLacker keeps its own account; disconnect the Yoink destination in its settings if you added one. Update destinations you configured (webhooks, Discord) receive nothing once the service is stopped.

Coming back

Reinstall from the repository, run npm install, npm run build and npm run service:install, then pair the companion again. A saved database copy placed at data/yoink.sqlite before the first start restores your plans; the README section Restore a backup has the exact steps.
