Install and pair on desktop Chrome

  1. Open Settings › Chrome and download the latest companion package. Extract the ZIP into a folder you will keep.
  2. Open chrome://extensions, enable Developer mode, choose Load unpacked, and select that folder. Managed distribution depends on your deployment; these instructions are for local installation.
  3. Back in Yoink, create a pairing code and use Copy code. Open the companion popup, enter your Yoink address and code, then pair. Codes expire; create a new one if needed.
  4. Settings › Chrome lists your paired browsers. Check the version and last activity; revoke a lost browser there.
  5. Open a supported product page. Grant store access when requested, inspect the product, and follow the store checklist. Sign-in, store checks and activation are separate steps. Store actions stay off until explicitly activated.

Start on Home by choosing Notify only or Add to cart, then choose an exact product and review your limits. You can save your first plan before connecting Chrome. Home shows what still needs setup. On your phone, use Copy desktop setup link after saving, then sign in to the same account on desktop to finish pairing. Notification-only plans can be saved before Chrome setup, but delivery still requires a working source and notification destination.

API source setup

Saving an API channel records its identity and trust; it does not create an endpoint, secret or sending client. Your deployment operator must provision the authenticated API sender and map its non-secret provider reference to the channel. Credentials belong in deployment secret storage, never in the channel name or reference.

  1. Agree on the sender, exact product identifiers and provider reference with your operator.
  2. The operator must follow the repository’s hosted deployment and source-ingress contracts for the running authentication mode. An endpoint URL alone is not authorization.
  3. Save the API channel as informational until identity matching has been checked.
  4. Have the operator send a test event with the configured client. Return to Sources and verify the accepted count, last event and matched product before relying on delivery.

Discord ingestion is unavailable in this release. Discord notification destinations are a separate, deployment-configured feature.

Connect a notification destination

  1. Ask your Yoink administrator to provision a Discord, Slack or webhook destination in the deployment and give you its non-secret delivery key.
  2. Open Settings › Notifications, enter the key, name the destination and select the events you want.
  3. Save, choose Test, and verify the message in the destination. A saved row alone does not prove delivery.
  4. Use Edit to change the name, events or delivery key. Pause stops new delivery through this destination.

If setup is pending, give your administrator the destination name and delivery key, plus the displayed error or request reference. Do not send webhook URLs, tokens or store account data.

Action flow

  1. A trusted call identifies one store item.
  2. Yoink applies the saved price, seller, delivery, quantity, and spending limits.
  3. The paired Chrome companion rechecks the live page and may click Add to cart once.
  4. Chrome confirms a +1 cart change before reporting Ready to check out.
  5. You finish checkout, then close the action as Got it or Missed it.

Connect TrackaLacker

  1. Stay signed in to TrackaLacker in Chrome.
  2. Open the Chrome companion popup.
  3. Choose Reconnect.
  4. Allow TrackaLacker page access when Chrome asks.

Yoink registers a browser push destination for the signed-in session. It does not store TrackaLacker cookies, CSRF values, or push keys.

Drop watch

An admin-authored drop window can place products in your Calls feed. After you opt in, the paired Chrome companion watches each item near the window until it appears in stock or the window closes. Watching never clicks Add to cart; a resulting call must still pass your plan and current store checks.

Glossary

Product terms

Plan
Your saved product, price, store, seller, delivery, quantity, and spending limits.
Store
A merchant where Yoink can recognize a product.
Call
A source event shown in your Yoink dashboard.
Sources
Services such as TrackaLacker, Discord, or an approved API channel that send calls to Yoink.
Rule
An admin-managed default that helps evaluate a call.
Settings
Your account and product configuration: Chrome pairing, notifications, spending limits, and privacy controls.
Chrome companion
The paired extension that checks the current store page and performs allowed actions in your signed-in Chrome session.
Quick add setup
Reusable limits you can select when using Quick add.
Notify-only setup
The built-in choice that creates notifications without cart actions.

Handoff stages

Queued
The cart check is waiting for the paired Chrome companion.
Checking
Chrome is checking the current store offer.
Ready to check out
The item was verified in the store cart. Finish checkout yourself.
Needs you
Chrome cannot safely infer the result. Review the store cart or session.
Closed
The action is finished. Close it with one of two choices: Got it records that you checked out and the amount charged for this item; Missed it records that checkout did not complete, with no spend.

Admin approvals

A protected change may require a recent sign-in or independent review. Independent review means a different authorized person must approve the exact operation, target, and bounded summary before the original person retries it. Approval does not apply the change by itself, expires after 15 minutes, and cannot be reused after the exact retry succeeds.

Safety boundaries

The dashboards keep this explanation here so action screens can stay concise.

  • Cart actions require the reviewed store item and first-party seller.
  • Each attempt adds one item and confirms a +1 cart change.
  • Shipping is the default; Pickup runs only when selected and currently available.
  • Chrome rechecks the current store page before it acts.
  • Checkout, payment, order submission, drawings, and challenge handling require you.
  • Yoink does not evade CAPTCHAs, send proxy store requests, or change carts outside your paired Chrome session.

Independent store checks

Page checks, sign-in state, price, seller, stock, delivery, and cart confirmation are evaluated separately for each store. One ready store never authorizes another.

Admin and diagnostics

Protected changes require deliberate confirmation, and widening changes may require a second authorized person. Hosted diagnostic views retain bounded operational evidence. Local repair captures can include sanitized product-page HTML; see the privacy policy for collection, retention and deletion controls.

Troubleshooting

No cart-ready cue
Open Activity, confirm the Chrome companion is paired, and review any action marked Needs you. The Chrome companion badge counts pending cart handoffs.
Store checks not ready
Open the store product page shown on the plan, then choose Inspect product in the Chrome companion popup. If the store remains unavailable, ask your Yoink administrator to review its store checks.
Product check stopped
Choose View details in the Chrome companion popup for the reason. Hosted diagnostics exclude page content, account data and secrets. Local repair snapshots are described in the privacy policy.
