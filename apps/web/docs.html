Install and pair on desktop Chrome

  1. Open Setup › Chrome and download the latest companion package. Extract the ZIP into a folder you will keep.
  2. Open chrome://extensions, enable Developer mode, choose Load unpacked, and select that folder. Managed distribution depends on your deployment; these instructions are for local installation.
  3. Back in Yoink, create a pairing code and use Copy code. Open the companion popup, enter your Yoink address and code, then pair. Codes expire; create a new one if needed.
  4. Setup › Chrome lists your paired browsers. Check the version and last activity; revoke a lost browser there.
  5. Open a supported product page. Grant store access when requested, inspect the product, and follow the store checklist. Sign-in and store checks are separate steps. Cart adds stay off at a store until you turn it on in Setup › Stores.

Tap Want it on a product, set the most you will pay per item, and choose Add to cart or Alert me. At Amazon, Target, Walmart and Best Buy, Add to cart also shows the item's MSRP for you to confirm, filled in from TrackaLacker or, when it reports none, the lowest Best Buy, Target or Walmart price; Yoink only adds the item at or below that MSRP. Fill in MSRPs on Wanted does this for every cart item at once. One tap covers every store that sells the product itself: Add to cart uses the stores that are on, and Alert me watches them all. When you turn a store on later, it joins the items you want added to cart. You can want items before connecting Chrome. Cart shows what still needs setup, what is ready to check out, your Wanted list, and the latest calls with what Yoink did with each one and why, such as over your max price or not on your Want list. Calls never add items to Wanted by themselves. While a supported store's product page is the tab in front, Chrome reads its stock and price when the page loads, when you come back to it, and every two minutes while it stays there, and each cart add does the same on its item's page; for items in Yoink, product cards then show Checked … · Chrome companion. Reading never clicks or changes the page, and when the page offers only another seller's listing, Yoink says so instead of calling it in stock. On your phone, use Copy desktop setup link after saving, then sign in to the same account on desktop to finish pairing. Alerts still require a working source and notification destination.

API source setup

Saving an API channel records its identity and trust; it does not create an endpoint, secret or sending client. Your deployment operator must provision the authenticated API sender and map its non-secret provider reference to the channel. Credentials belong in deployment secret storage, never in the channel name or reference.

  1. Agree on the sender, exact product identifiers and provider reference with your operator.
  2. The operator must follow the repository’s hosted deployment and source-ingress contracts for the running authentication mode. An endpoint URL alone is not authorization.
  3. Save the API channel as informational until identity matching has been checked.
  4. Have the operator send a test event with the configured client. Return to Sources and verify the accepted count, last event and matched product before relying on delivery.

Discord messages reach Yoink through your Windows notifications; see Discord calls. Discord notification destinations are a separate, deployment-configured feature.

Connect a notification destination

  1. Ask your Yoink administrator to provision a Discord, Slack or webhook destination in the deployment and give you its non-secret delivery key.
  2. Open Setup › Alerts, enter the key, name the destination and select the events you want.
  3. Save, choose Test, and verify the message in the destination. A saved row alone does not prove delivery.
  4. Use Edit to change the name, events or delivery key. Pause stops new delivery through this destination.

If setup is pending, give your administrator the destination name and delivery key, plus the displayed error or request reference. Do not send webhook URLs, tokens or store account data.

Action flow

  1. A trusted call identifies one store item.
  2. Yoink applies the saved price, seller, delivery, quantity, and spending limits.
  3. The paired Chrome companion rechecks the live page and may click Add to cart once, at the store's current price when that is at or under your max (it need not match the call's price). When Amazon features another seller's offer and also lists its own, Chrome first picks Amazon's own offer if its price is within your plan.
  4. Each cart add runs in one tab from start to finish: Chrome reads your cart first, so it can prove exactly what it adds, then opens the item in the same tab, adds it, and goes back to the cart in that tab once the store has had a moment to finish. It confirms the exact cart change before reporting Ready to check out, then opens checkout in that same tab at Walmart, Target, Amazon and Best Buy; no other tab is left behind. At Best Buy the item page stays put after Add, because Best Buy may hold you in a queue there, so the cart is checked in a second tab that closes once checkout opens. If the store shows its robot or security check (such as Walmart's Press & Hold), Chrome stops, says so in the call log, and leaves that tab open for you to finish it. If the item turns out to be sold out, or the add stops before anything was added, Chrome closes that tab. With Retry when sold out on in Setup › Stores, Yoink instead reloads the same tab and tries again when the store itself didn't have it (sold out, or only another seller had it), up to the number of tries you set, spread over your window and at least 30 seconds apart; each try checks the price, seller and stock again and never adds a second one. To try this without waiting for a restock, use Test call in Setup › Stores: pick an item you want added to your cart, or paste any in-stock product link from that store (or the SKU shown on a Best Buy page) with the most you'll pay, and Yoink sends one call for it, labelled TEST; Chrome adds it at the store's price when that's at or under your max. Nothing is ordered; remove the item from your cart afterwards if you don't want it. Each linked item stays under Saved test items in that store's Test call, with your max, quantity and the stock Chrome last saw, so Test again sends it once more.
  5. With the item in your cart, Chrome opens checkout, brings that window to the front and alerts you. A call Yoink didn't add raises no Windows alert: Cart › Calls lists it with the reason.
  6. You finish checkout, then close the action as Got it or Missed it.

Connect TrackaLacker

  1. Stay signed in to TrackaLacker in Chrome.
  2. Open the Chrome companion popup.
  3. Choose Reconnect.
  4. Allow TrackaLacker page access when Chrome asks.

Yoink registers a browser push destination for the signed-in session. It does not store TrackaLacker cookies, CSRF values, or push keys. After a Yoink update the companion reconnects to TrackaLacker by itself, through your open TrackaLacker tab or one it opens in the background and closes again.

Your followed TrackaLacker products stay current by themselves: every hour the companion refreshes their prices and stock, and overnight it also reads History for MSRPs not checked in the last week. Sync products in the companion menu runs that full pass now. If TrackaLacker asks it to slow down or to sign in, it stops and tries again later.

Discord calls

When Yoink runs on your Windows PC, it reads the Discord messages Windows shows as notifications, from the Discord app or from Discord in a browser such as Brave, and matches each one to a Yoink product. It needs no Discord bot or sign-in, but a message must reach Windows' notification centre: turn on Discord's desktop notifications for the channels you follow, and allow Discord's notifications in Windows. A message that is only an embed or an image has no text in its notification, so Yoink can't read a product from it.

  1. A message becomes a call when it names a store item, stock or a price, or comes from a store-alert channel such as #target-restocks. Chat, questions, DMs and every other app's notifications are skipped and not kept.
  2. Yoink matches the call to a product in this order: a store link in the message, a store item number (SKU, TCIN, ASIN or UPC), a product name you linked before, then the product name itself. A store link can be the product page, an add-to-cart link, a store link inside an affiliate link, or a short link such as amzn.to, a.co, bit.ly or howl.me; Yoink asks the short-link service where it leads, never any other site, and goes by the message's other words if it can't tell. A name only matches when it clearly fits one product better than any other; otherwise the call is listed as not matched. The store comes from the link, the store the message names, or the channel's name; when none is named, Yoink uses the product's only store, or checks each store you want the product from, or else lists the call as No store named.
  3. A store link for an item that isn't in Yoink yet is added to Yoink, like an item a TrackaLacker call names: as that store's listing of the product the message names when Yoink doesn't have it at that store, or as a new product named from the message, or from the store page's address when the message names no product. Want it there to have Yoink add it to your cart; a name match never puts an item in your cart on its own.
  4. Not every message is about a product. A notice that names none, such as a monitor's status, a teaser or news, and a message whose links land on a store's search, category, drawing or queue page instead of a product's page, is listed as a notice and nothing more. A message that lists several items becomes a call for each. A drop, drawing or queue time in a message (“Drawing starts Oct 14, 2:00pm PDT”, “drops tomorrow 9am ET”) is shown with its call, read in the time zone it names or else your PC's. For a drop or queue time of an item Yoink has at a store it watches, Yoink sets a drop window: with Watch drops for wanted items on, or after you choose Watch, Chrome checks the item's page from 15 minutes before, and your plan decides whether to add it. A drawing gets no window, since you enter it at the store.
  5. A matched call goes through your plan like a TrackaLacker call: Chrome opens the store's page, checks that the store itself sells it in stock at or under your max, and adds it. At Amazon, Target, Walmart and Best Buy a price the message states must also be at or under the MSRP and max you saved. A message without a price is checked on the store's page alone, against your max, which is never above the MSRP. Prices from Discord messages never go into a product's price history.
  6. Cart › Calls › Discord lists every Discord call with the message, the product it was matched to and how. For a message Yoink couldn't match, choose Link product and pick the product; later messages with the same product words match it.
  7. Setup › Discord shows whether Yoink can read your notifications and lists each channel that has sent a call. Each channel can Add to cart (the default), Log only or be ignored. Turning Read Discord notifications off stops reading them; notifications that arrive while it is off are never read.

Drop watch

An admin-authored drop window can place products in your calls. After you opt in, the paired Chrome companion watches each item near the window until it appears in stock or the window closes. Watching never clicks Add to cart; a resulting call must still pass your plan and current store checks.

Glossary

Product terms

Plan
Your saved product, price, store, seller, delivery, quantity, and spending limits.
Store
A merchant where Yoink can recognize a product.
Call
A source event shown in your Yoink dashboard.
Sources
Services such as TrackaLacker, Discord, or an approved API channel that send calls to Yoink.
Rule
An admin-managed default that helps evaluate a call.
Setup
One page for your stores, Chrome pairing, Discord, alerts, spending limits, and your data.
Auto-cart
The one switch at the top of Yoink. On, Yoink may add wanted items to your cart at stores that are on; off, Yoink only logs calls and sends them to any alert destination you set up.
Chrome companion
The paired extension that checks the current store page and performs allowed actions in your signed-in Chrome session.
Want it
One tap on a product: Yoink adds it to your cart, or with Alert me logs the call and sends it to any alert destination you set up, when a store that sells it has it in stock at or under your max price. Once you want it, its button reads Yoink; tap it to change or stop what Yoink does. For cart adds, Any price up to my max skips the MSRP check: Yoink adds it at the store’s own price, up to your max, and never from a third-party seller. Want it also charts each store’s recorded prices, with the MSRP and your max for reference. Under the chart are the 90-day low and high and Yoink suggests: each store’s usual price over 90 days, so short spikes don’t count, and the highest of the stores within $5 or 10% of the cheapest one. Use as my max sets your max to it.
All New
A TrackaLacker entry such as All New NeeDoh or All New Pokemon that gathers a brand’s new items. Each item is its own product, marked Part of All New …, and the same item at several stores is one product with each store’s price; filter by a store to see only its own. Yoink tells items apart by their barcode (UPC): the Chrome companion reads it from a store’s page whenever it has one open, and opens each new All New item’s Walmart, Target or Best Buy page once in a background tab to read it, a few pages at a time. The same barcode is one product whatever the names say, and different barcodes never are; until an item has a barcode, Yoink goes by its name and price. If a store answers with a bot check, those visits stop there for six hours. The details sheet shows each store’s UPC. Want it on the entry wants every item, now and each new one as a sync or a call finds it: Alert me, or Add to cart at any price up to the item’s max. Each item’s max is Yoink suggests, or its first store price while it is new, and follows the suggestion as prices are recorded. Items you set up yourself, paused, or removed from Wanted stay as you left them; Stop wanting removes only the items the entry added.
Quick add setup
Older reusable limits. Want it replaced them; existing items keep the limits they were saved with.

Handoff stages

Queued
The cart check is waiting for the paired Chrome companion.
Checking
Chrome is checking the current store offer.
Ready to check out
The item was verified in the store cart. Finish checkout yourself.
Needs you
Chrome cannot safely infer the result. Review the store cart or session.
Closed
The action is finished. Close it with one of two choices: Got it records that you checked out and the amount charged for this item; Missed it records that checkout did not complete, with no spend.

Admin approvals

A protected change may require a recent sign-in or independent review. Independent review means a different authorized person must approve the exact operation, target, and bounded summary before the original person retries it. Approval does not apply the change by itself, expires after 15 minutes, and cannot be reused after the exact retry succeeds.

Safety boundaries

The dashboards keep this explanation here so action screens can stay concise.

  • Cart actions require the reviewed store item and first-party seller.
  • Each attempt adds what the plan still needs, never more than the store allows per order, and confirms the exact cart change.
  • Shipping is the default; Pickup runs only when selected and currently available.
  • Chrome rechecks the current store page before it acts.
  • Checkout, payment, order submission, drawings, and challenge handling require you.
  • Yoink does not evade CAPTCHAs, send proxy store requests, or change carts outside your paired Chrome session.

Independent store checks

Page checks, sign-in state, price, seller, stock, delivery, and cart confirmation are evaluated separately for each store. One ready store never authorizes another.

Admin and diagnostics

Protected changes require deliberate confirmation, and widening changes may require a second authorized person. Hosted diagnostic views retain bounded operational evidence. Local repair captures can include sanitized product-page HTML, and a store's cart page when it couldn't be read; see the privacy policy for collection, retention and deletion controls.

Troubleshooting

No cart-ready cue
Open Cart, confirm the Chrome companion is paired, and review any cart marked Needs you. The Chrome companion badge counts pending cart handoffs.
Store checks not ready
Open Setup › Stores and choose Details for the store. Open an available product from that store in Chrome, then choose Inspect product in the Chrome companion popup. On a shared Yoink, your administrator turns stores on.
Product check stopped
Choose View details in the Chrome companion popup for the reason. Hosted diagnostics exclude page content, account data and secrets. Local repair snapshots are described in the privacy policy.
